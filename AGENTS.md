# Neorism 1.7.10 — Agent Rules

> **Проект:** Бэкпорт *Vampirism: Become a Vampire* (`maxanier` / `TeamLapen`) на Forge 1.7.10 (GTNH Gradle / RFG, Java 25 + Jabel).  
> **Пакет:** `com.marrybye.neorism` (`api`, `client`, `common`). Контекст и прогресс: `docs/PROJECT_CONTEXT.md`, `docs/BACKPORT_ROADMAP.md`.

## 1. Формат общения (Token Economy)
- **Максимальная краткость:** Отвечать строго в **1–2 предложения** без воды и пересказа кода. Если пользователю нужны детали, он запросит репорт (`task-reporting`).
- **Исключение:** Критические архитектурные выборы, блокеры, неоднозначности или серьезные проблемы — описывать подробно и полностью.

## 2. Главные ограничения
- **Каноничность кода (`canonical-backport`):** ЗАПРЕЩЕНО писать механики/формулы/константы «из головы». Всегда находить исходник в `reference/vampirism/` (`de.teamlapen.vampirism`, `de.teamlapen.faction`) и точно адаптировать под 1.7.10.
- **Запрет своих текстур и моделей:** НЕ создавать свои текстуры и НЕ создавать свои модели — все оригинальные ассеты уже есть в проекте и `reference/vampirism/`. Если создание кастомного ассета необходимо, только предложить это как идею пользователю и ждать его решения (да/нет).
- **Атрибуция и лицензии:** Сохранять авторство `maxanier`/`TeamLapen` и дисклеймер (баги Neorism не относятся к оригиналу). Код — LGPL-3.0, ассеты/лор — некоммерческие лицензии Vampirism.
- **Стек GTNH:** Учитывать совместимость с `Angelica` (не ломать GL-стейт), `GTNHLib`, `Hodgepodge`, `Et-Futurum-Requiem`, `VillageNames`, `lwjgl3ify`, `UniMixins`, `Combat Backport`, `Villager Trades Backport`.

## 3. Git и Релизы
- **Локальные коммиты:** Фиксировать каждое логическое изменение локально в формате Conventional Commits: `<type>(<scope>): <description>` (`feat`, `fix`, `refactor`, `perf`, `docs`, `chore`, `test`).
- **Запрет Push:** НИКОГДА не делать `git push` и релизы без прямой команды пользователя (*"заливаем на гитхаб"*, *"создай релиз"*).
- **Релиз (по команде):** Проверить лог с прошлого тега (`git log <last-tag>..HEAD --oneline`), определить SemVer (`v0.1.x` fix, `v0.x.0` feat, `v1.0.0` major), создать аннотированный тег (`git tag -a vX.Y.Z -m "..."`), запушить с тегами (`git push origin master --tags`) и оформить GitHub Release.

## 4. Рабочий процесс и Скиллы (`.agents/skills/`)
- **Логгирование (`debug-logging`):** Ключевые события (бой, ИИ, уровни, спавн, торговля, ритуалы) логгировать через `ModLogger`, обернув во флаги `Config.debugLogging`.
- **Сборка и Тесты (`run-client-test`):** Компилировать через `.\gradlew assemble`. Не копировать jar-файлы зависимостей/мода в `run/client/mods/`. Клиент запускает ТОЛЬКО пользователь (`runClient25`). Логи (`fml-client-latest.log`, `latest.log`, краши) проверять по команде.
- **Отчеты (`task-reporting`):** Отчеты в `docs/reports/DD-MM-YYYY-HH-MM-TITLE.md` создавать **ТОЛЬКО по явному запросу пользователя** на основе git-коммитов с момента последнего отчета. **НЕ читать и НЕ изменять репорты после создания** (режим write-only для экономии токенов).
